Step 1: Create a DynamoDB Table
1. Sign in to the Amazon Web Services console: AWS Management Console.
2. Search for DynamoDB.
3. Open DynamoDB and select Tables.
4. Click Create table.
5. Enter the following details:
Setting	Value
Table name	RegistrationTable
Partition key	email
Partition key type	String


6. Leave the other settings at their defaults for this practical.
7. Click Create table.
8. Wait until the table status becomes Active.
Why use email as the partition key? DynamoDB uses a partition key to identify items. Using email makes each email address unique in this example.
Step 2: Create an IAM Role for Lambda
Lambda needs permission to write data to DynamoDB.
1. Search for IAM in the AWS console.
2. Select Roles from the left menu.
3. Click Create role.
4. Under Trusted entity type, select AWS service.
5. Under Use case, select Lambda.
6. Click Next.
7. Search for and select this AWS-managed policy:
   AmazonDynamoDBFullAccess
8. Click Next.
9. Enter the role name:
   LambdaDynamoDBRegistrationRole
10. Click Create role.
Important security note
AmazonDynamoDBFullAccess is convenient for a quick lab, but it grants broader access than necessary. For a real application, use a custom IAM policy that allows only dynamodb:PutItem on RegistrationTable.
Step 3: Create the Lambda Function
1. Search for Lambda in the AWS console.
2. Click Create function.
3. Select Author from scratch.
4. Enter these settings:
Setting	Value
Function name	RegistrationFunction
Runtime	Python 3.x runtime available in your console
Architecture	Default
Permissions	Use an existing role


5. Under Existing role, select:
   LambdaDynamoDBRegistrationRole
6. Click Create function.
Your Lambda function is now created.
Step 4: Write the Lambda Function
1. Open RegistrationFunction.
2. Scroll down to the Code section.
3. Open the file lambda_function.py.
4. Delete the existing sample code.
5. Paste the following code:
import json        # Validate required fields        if not name or not email or not phone:            return {                "statusCode": 400,                "headers": {                    "Content-Type": "application/json"                },                "body": json.dumps({                    "message": "Name, email and phone are required"                })            }        # Store registration in DynamoDB        table.put_item(            Item={                "email": email,                "name": name,                "phone": phone            },            ConditionExpression="attribute_not_exists(email)"        )        return {            "statusCode": 201,            "headers": {                "Content-Type": "application/json"            },            "body": json.dumps({                "message": "Registration successful"            })        }    except dynamodb.meta.client.exceptions.ConditionalCheckFailedException:        return {            "statusCode": 409,            "headers": {                "Content-Type": "application/json"            },            "body": json.dumps({                "message": "This email is already registered"            })        }    except Exception:        print("Registration failed")        return {            "statusCode": 500,            "headers": {                "Content-Type": "application/json"            },            "body": json.dumps({                "message": "Internal server error"            })        }


6. Click Deploy to save the code.
Understanding the important code
Code	Purpose
import boto3	Uses the AWS SDK for Python.
boto3.resource("dynamodb")	Connects the function to DynamoDB.
table.put_item()	Inserts registration data into the table.
json.loads(body)	Converts JSON text into a Python dictionary.
statusCode: 201	Indicates successful creation of a registration.
ConditionExpression	Prevents inserting another item with the same email key.


Important: This code assumes the form sends JSON fields named name, email, and phone. If your provided form uses different field names or sends URL-encoded form data, the Lambda code must be adjusted accordingly.
Step 5: Test the Lambda Function
Before connecting the registration form, test Lambda directly.
1. Open RegistrationFunction.
2. Click the Test tab or Test button.
3. Create a new test event.
4. Enter the event name:
   RegistrationTest
5. Replace the event JSON with:
{
  "body": "{\"name\":\"Iffat\",\"email\":\"iffat@example.com\",\"phone\":\"9876543210\"}"
}

6. Save the test event.
7. Click Test.
Expected output
You should receive a response similar to:
{
  "statusCode": 201,
  "headers": {
    "Content-Type": "application/json"
  },
  "body": "{\"message\": \"Registration successful\"}"
}

If you run the same test again with the same email, the function should return status code 409 because that email is already registered.

If you receive an error: Check the Lambda execution role, table name, AWS Region, and test event format.
Step 6: Connect Lambda to API Gateway
To submit data from a browser-based registration form, we need an HTTP endpoint. We will create one using API Gateway.
A. Create an HTTP API
1. Search for API Gateway in the AWS console.
2. Click Create API.
3. Find HTTP API and click Build.
4. Enter an API name, for example:
   RegistrationAPI
5. Add an integration:
   - Integration type: Lambda
   - AWS Region: The same Region as your Lambda function
   - Lambda function: RegistrationFunction
6. Configure the route:
Setting	Value
Method	POST
Resource path	/register


7. Create or select the default stage, usually $default.
8. Enable automatic deployment if that option is available.
9. Review and create the API.
Your API will provide an Invoke URL, similar to:

https://example123.execute-api.ap-south-1.amazonaws.com

This is only an example. Copy the actual URL shown in your AWS console.
B. Understand the endpoint
The registration form will send its data to:

YOUR_API_INVOKE_URL/register

Replace YOUR_API_INVOKE_URL with your actual Invoke URL. If your API uses a named stage rather than $default, include that stage in the URL.
Step 7: Configure CORS
CORS allows a browser to make requests to an API hosted on a different origin.

If the registration form is hosted on a different origin from API Gateway:
1. Open your API in API Gateway.
2. Find CORS settings.
3. Configure the following for this lab:
Setting	Value
Allowed origins	Your form's origin, or * for a temporary lab
Allowed methods	POST, OPTIONS
Allowed headers	content-type


4. Save the changes.
For a real application, restrict allowed origins to your actual website. Avoid using * unnecessarily.
Step 8: Connect the Provided Registration Form
Since your practical says the registration form code will be provided, you generally only need to connect its submission logic to your API.

For example, if the form contains these HTML fields:
<form id="registrationForm">
    <input type="text" id="name" placeholder="Name" required>
    <input type="email" id="email" placeholder="Email" required>
    <input type="tel" id="phone" placeholder="Phone" required>

    <button type="submit">Register</button>
</form>

<p id="result"></p>

Add this JavaScript before the closing </body> tag:
<script>
document.getElementById("registrationForm")
    .addEventListener("submit", async function(event) {

    event.preventDefault();

    const data = {
        name: document.getElementById("name").value,
        email: document.getElementById("email").value,
        phone: document.getElementById("phone").value
    };

    try {
        const response = await fetch(
            "YOUR_API_INVOKE_URL/register",
            {
                method: "POST",
                headers: {
                    "Content-Type": "application/json"
                },
                body: JSON.stringify(data)
            }
        );

        const result = await response.json();

        document.getElementById("result").textContent =
            result.message || "Request completed";

    } catch (error) {
        document.getElementById("result").textContent =
            "Unable to connect to the registration service.";
    }
});
</script>

Replace YOUR_API_INVOKE_URL/register with the actual endpoint you created in Step 6.

If the registration form has already been provided, do not replace its existing HTML unnecessarily. Modify its JavaScript submission handler to send the correct field names to the endpoint.
Step 9: Verify the Data in DynamoDB
After submitting the form:
1. Open DynamoDB in the AWS console.
2. Click Tables.
3. Open RegistrationTable.
4. Select Explore table items.
5. Click Run or refresh the results.
You should see a record similar to this:
email	name	phone
iffat@example.com	Iffat	9876543210


This confirms that the registration data has been stored successfully
